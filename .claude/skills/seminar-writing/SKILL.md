# 固定資産仕訳セミナーの整理と記述のルール

## 整理の基本姿勢

受講者向けの内容ではなく、内容を整理・記述するときの約束事。スライドには載せない。

- 仕訳の形はユーザーごとの方針で変わる。「必ずこうなる」と断定せず、基本となる考え方を書く。よくある形は「事例が多い」「一般的」と書き、決めつけない
- 仕訳の形がユーザーごとに変わることは資料全体の前提なので、「〜はユーザーによる」「〜は方針による」「〜するユーザーもある」とは書かず、ありうるケースを説明の中に「〜することも、〜することもある」と並べて書く（2026-11-23）。「バリエーション」の箇条や表の列、「基本となる考え方：」のような見出しを別に立てない。選択肢を「／」で並べず、文で書く（2026-11-23）
- 仕訳例は、ある方針を採った場合の一例として示す
- 「確認すべきポイント」や検証チェックリストは書かない（2026-11-22）。何が起きうるか・何が方針で変わるかを書けば足りる
- どの項目の話かが分かるよう、ERPの項目名は［勘定科目］のように括弧で示す
- 繰り返し・重複を避ける。要件・入力項目・勘定科目の説明は1か所にまとめ、伝票の種類ごとの節では各伝票に固有の点だけを書き、ほかは参照先（「1-2 のとおり」など）を示す
- 細かい説明は、扱う章の1か所に置く。1章は要件の粒度で書き、どの項目をどう持つか（取引先・税区分を持たせる行など）は2章、勘定科目の分け方（製造原価・販管費の区分の持ち方など）は3章、伝票の種類によって変わること（伝票の切り方、会計日付、取引先を固定資産システムで編集するかなど）は4章に置く。同じ説明や注意書きを別の章で繰り返さない（2026-11-23）
- 節どうしの参照は、骨子の本文とは別に、リポジトリの `骨子_節の関係.csv`（列：from,to,relation,body）で管理する。説明は概要から詳細に下りていくので、本文には後ろの節・章への参照を書かない（同じ章の中も）。前の節・章への参照は、前に説明したどの内容とつながるかを示すと理解の助けになる場合だけ、意図して書く（2章・3-1の「関係する要件」の列など）。本文に参照を足す・外すとき、節どうしの関係を見つけたときは、CSV の行を足し、body を「残す」「外す」で更新する（2026-11-23）
- 同じ章の節は、記載の粒度と並びをそろえる（章ごとの並びは references/骨子の構成.md）
- 特定のERPパッケージに引きずられた用語（モジュール、機能領域など）を使わず、一般的な言葉で書く
- 「重要になる」「注意が必要」「意識する」のような、何をどうするかが分からない表現で終わらせない。具体的に何を分ける・そろえる・記録する必要があるかを書く
- 直接法・間接法、帳簿価額、配賦、直接控除形式・間接控除形式、直接減額方式・積立金方式などの一般の会計用語は、言いかえずにそのまま一貫して使う。カッコで意味を言いかえることもしない
- 本資料で定義する言葉（固有名詞として扱う言葉）と一般的な表現を区別する。一般的な表現（用途＝使い道、など）は普通の意味で使い、特別な意味を持たせない。そのスライドの文脈の中で意味が通り、資料全体で同じ使い方になっていればよく、別の箇所の使い方と衝突するとして言いかえる必要はない（2026-11-25）
- 本資料で定義する言葉（固定資産勘定、費用・収益の勘定、債権・債務、セグメント、個別仕訳・定型仕訳など）は、骨子で最初に出る箇所で一言定義し、後の章で定義を繰り返さない。同じ意味を別の言い方（例：個別仕訳を「日次で取引ごと」）で書かない
- 説明なしに出てくる言葉（例：勘定科目テーブル、機能区分、反転、仕訳ファイル）を残さない。言いかえるか、要らなければ外す（2026-11-23）
- 「なぜそうなるか」（例：なぜ一致が崩れるか、なぜ消し込みが必要か）を省かない
- 表の「関係する要件」などの列に「－」を残さない。埋まらない場合は、1章の要件の書き方を見直す
- 「関係する要件」の列には、参照先の節の本文に対応する説明があるものだけを書く。1章に説明のない目的（例：数量と原価管理）を、列の中だけで結びつけない（2026-11-23）
- 「要件」は1章の要件（1-1〜1-4）の意味だけで使う。ユーザーの事情の意味で「要件による」「要件次第」とは書かない（2026-11-23）
- 聞き手に向けた内容と、書き手（Claude）への指示を混ぜない。後者は骨子の前提条件かこのファイルに置き、スライドには載せない（例：「1〜3章は繰り返さず」のような書き方の約束事を、骨子の本文に書かない）
- 骨子の構成と、用語の定義はテーマ別に references/ に置いた（2026-11-22）。書く・直す前に、関係するファイルを読む

## リファレンス（references/）

骨子のテーマ（章）ごとに、用語の定義・統一する書き方と、調査で分かったことの要点を置く。用語のファイルの言葉は、骨子・スライド・ノートの言葉の基準になる。同音異義・多義の言葉は定義した意味だけで使い、意味のない言いかえはしない。

| ファイル | 内容 | 読むとき |
|---|---|---|
| [骨子の構成.md](references/骨子の構成.md) | 全体の構成、1章・2章の組み立て、ERPの項目の前提 | 章・節を足す・並べ替える、要件との対応を書くとき |
| [1_仕訳の要件.md](references/1_仕訳の要件.md) | ERP・連携・台帳・元帳・帳簿・同期・照合とシステムの呼び方。管理会計の用途と業種、他システムとの照合（照合キー・粒度・仕訳の分担の形・資産の例・消費税）の調査の要点 | 1章、システム間の話を書くとき |
| [2_仕訳の入力項目.md](references/2_仕訳の入力項目.md) | セグメント・用途・伝票番号・参照番号・会計日付・伝票日付。ERP 4製品の仕訳ファイルの調査の要点 | 2章、項目の話を書くとき |
| [3_勘定科目.md](references/3_勘定科目.md) | 資産勘定・固定資産勘定・累計額・費用・収益の勘定・債権・債務・減価償却 | 3章、勘定科目の言葉を使うとき |
| [4_伝票の種類.md](references/4_伝票の種類.md) | 伝票の種類・振替と、仕訳例の勘定科目名・セグメント・取引先 | 4章、仕訳例を書くとき |
| [文章の表記.md](references/文章の表記.md) | 方針・設定、例・仕訳例・バリエーションなど、テーマによらない表記 | 常に |

調べた内容の詳しい記録（経緯・出典・確かさ）は、リポジトリの `調査メモ/` に置く（一覧と書き方は `調査メモ/README.md`）。references/ には、骨子を書くのに要る要点だけを、テーマの合うファイルにまとめ、詳しくは調査メモを参照させる。調査のための言葉（製品名、「連動」など）は、references/ に書いても、骨子・スライドには持ち込まない

## スライドへの載せ方

スライドの題・リード文・中身は、骨子の「スライドに反映する内容」と一緒に決める。技術的な手順（クラス、計測、書き出し）は seminar-slides。

### 関連する節との整合性を確かめる

- スライドの題・リード文・中身を検討する（作る・直す・提案する）ときは、その枚だけで決めず、関連する節との整合性を確かめてから決める（2026-11-26）
  - `骨子_節の関係.csv` で、その枚の節を from・to に持つ行を引き、関連する節の骨子とスライド（骨子5章の表で枚を引く）を読む
  - 全体像の枚と詳細の枚（例：7枚目と8〜14枚目、25枚目と26〜31枚目）は、列・行の名前、並び、中身が食い違っていないかを、両方向で確かめる
  - 前の章の言葉・図（例：1章の同期をとる対象、①〜③の名前）を後の章で使うときは、同じ言葉・同じ範囲になっているかを確かめる
  - 食い違いを見つけたら、直す枚だけでなく関連する枚・骨子の節も直すか、直し方を示して確かめる。CSV にない関係を見つけたら行を足す
- 1枚を直したら、同じ言葉・同じ表を写している枚と骨子の箇所（5章のスライド名、全体像の表など）も grep してそろえる

### 載せるものとノートに回すもの

- 用語だけを集めたスライドは作らない。本資料で定義する言葉の定義（「本資料の呼び方」）は、スライドに枠や注記で載せず、その言葉が初めて出るスライドのノートで話す。読み手の理解を促さず、ノイズになるため（2026-11-24）
- スライドは情報を詰め込まない（2026-11-24）
  - スライドに載せるのは、見て分かる必要があるもの：表、図、仕訳例と、短い題・リード文、多くても3行程度の箇条
  - 見せなくても話せば伝わるもの（理由・背景、ケースの説明、言葉の補足、具体例の説明、前後のつなぎ、例の断り書き）は、ノート（`<aside>`）にだけ書く
- 「扱わないこと」を、前置き（なぜ扱わないか）や基準（どこで線を引くか）なしにスライドに並べない。ノートで話す（2026-11-24）
- 1つの事例から一般化した注意書き（例：「費用・収益の行は取引の時点のセグメントで計上し、その後に台帳を変更しても振り替えない」）をスライドに載せない。その枚で伝える点に関係しない注意書きは外す（2026-11-26）
- 骨子でもこの区別を示す：ノートにだけ書く段落は引用（`> `）にし、ノートに回す表の列は列名に〔ノート〕を付ける。印のない本文と表がスライドに載せる内容。本資料で定義する言葉の定義は、ノートにだけ書く内容として印を付ける。骨子を直すときは、スライドとノートの分け方もこの印で決める（2026-11-24）

### 題（タイトル）

- 題は、その枚の中身を誤解なく表す。一部の場面にしか当てはまらない言い方にしない（例：振替では勘定科目・セグメントが変わるので、「増加・振替・減少で勘定科目・セグメントをそろえる」とせず「仕訳の勘定科目・セグメントを、その時点の台帳の資産に合わせる」とした）（2026-11-25）
- 1章の固定資産システムの仕訳の要件は、全体像の枚（7枚目）と同じ ①②③ の番号を、題とラベルに付ける
- 例を挙げるだけで、それ以上の意味がない枚は、題に「〜の例」と付ける（例：③ 照合の相手のシステムの例）（2026-11-25）
- 詳細の枚の題は、全体像の枚の行の名前（伝票の種類など）とそろえる
- 同じ話題が2枚に分かれるときは「減価償却費①：集約と配賦」「減価償却費②：…」のように、番号と「：」の後ろにその枚の中身を書く
- 題の上のラベルは「章の番号 章の名前｜節」とし、1章はERPの仕訳の要件か ①〜③ のどれか、2章はヘッダか明細かを示す。3章・4章は章の名前だけ

### リード文

- リード文（題の下の文）は、その枚の要点（聞き手に持ち帰ってほしいこと）を明示する。1文が基本で、要点が2つあるときは2文にしてよい（2026-11-26）
- 主体と言い方は、その章の文脈に合わせる。無理に主体をそろえない（2026-11-25）
  - 1章：固定資産システムの仕訳の要件や作り方を示す枚は、主体を固定資産システムの仕訳とし（主語は書かない）、仕訳として何をするかを「〜を…する」で書く
  - 2章：一般的なERPの仕訳の入力項目の説明として、項目を主体に「〜は…を持つ」「〜を表す」などで書く
  - 3章：導入先の勘定科目の体系で決まっている勘定科目の説明として、勘定科目を主体に書く（「〜を決めておく」とは書かない）
  - 4章：伝票の種類の説明として、伝票の種類を主体に、その伝票の種類で気を付ける点を書く
- 全体像の枚（一覧の表）は、表から読み取ってほしいことを書く。何によって何が異なるかが要点なら「〜によって、…が異なる」と書いてよい（例：「伝票の種類によって、関連する要件が異なる」）
- ほかの枚に「合わせて」と言われたときは、文の形ではなく中身（その枚の要点を明示すること）をそろえる。「〜によって変わる」のような文型に全部をそろえない（2026-11-26）
- 章の切り替えの枚は、これから何を見るかを「ここからは、〜を見る」と書く
- 例を挙げるだけの枚は、例であることを書く（例：「照合の相手として考えられるシステムの例」）
- 次のような書き方をしない
  - 要らない修飾（「いつの時点でも」「台帳の資産の情報から」「一度」など）や、同じことの言い直し（「伝票の種類は伝票の種類で…」）
  - ケースを狭めすぎる言い方（相手のシステムを債権・債務管理システムだけにする、相手のシステムがない場合を落とす、など）
  - その場で決めるように読める言い方（「範囲を決める」「都度決める」）。方針は企業ごとに決まっているので、何がどう決まっているかを書くか、ノートに回す
  - 「範囲」「対応する」のような、何を指すか分からない言葉で終わらせる
  - 実際には順序が決まっていないことを決めつける（例：減価償却費は毎月の定型仕訳で先に計上し、後から売却・除却を登録することもあるので「先に計上する」と書かない）

### 表・図

- 1枚に載せる表・仕訳例の図は1つまで。表は、話すための列（業種の例、つながり方など）をノートに移して列を減らす。例外は骨子5章に枚ごとに書く
- 同じ話題の枚は1枚にまとめる（例：伝票の単位と日付、［取引先］と［税区分］）
- 詳細の枚は、全体像の枚の列・行に合わせる。全体像の表のどの列の詳細かを決め、中身をその列の観点に絞る（例：28枚目は25枚目の「② 費用・収益の計上」の列に合わせ、費用・収益の行に持たせるセグメントに絞った）。全体像の表から外した内容は、詳細の枚にも残さない
- 列名・行名と、並べる項目の粒度を資料全体でそろえる（例：列名は「目的」で統一。ROICのような指標名ではなく「投資効率の評価」と、ほかの行と同じ粒度で書く）
- 例は、ルールほど強く見えないようにする（列名を「照合の単位の例」とする、セルの中では灰色の小さい字にする）
- 4章のように仕訳の形を示す枚は、仕訳例を中心にした表にする。文で説明する列は作らない
- 要件のように、あるべき姿を伝える枚は、「あるべき」と「残高が残る」の仕訳・残高を並べ、元帳の残高がきれいに消えることを見せる
- 章・節が変わるところや、新しい概念（他システムなど）が初めて出るところには、つなぎの1枚を置く
- 評価勘定（減価償却累計額など）の残高には △ を付ける。台帳の行は、元帳と比べやすいようセグメントの順に並べる

## メンテナンス

- 用語を足す・変えるとき、調査メモを足したときは、テーマの合う references/ のファイルを更新し、骨子・スライド・ノートを grep して表記をそろえる。合うテーマがなければファイルを足し、上の表に加える
- 用語は1つのファイルにだけ書く（定義が2か所に分かれないようにする）
- 変更は骨子の決定事項ログにも残す
- 節の内容を移す・削るときは、`骨子_節の関係.csv` でその節を参照先（to）にしている行を探し、本文の参照（「1-4 のとおり」など）と、内容を写している表（2章・3-1・4-1 の表、5章のスライド名、未決事項の節番号）も合わせて直す（2026-11-23）
