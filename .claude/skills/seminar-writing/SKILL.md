# 固定資産仕訳セミナーの整理と記述のルール

## 整理の基本姿勢

受講者向けの内容ではなく、内容を整理・記述するときの約束事。スライドには載せない。

- 仕訳の形はユーザーごとの方針で変わる。「必ずこうなる」と断定せず、基本となる考え方とバリエーションとして書く
- 「仕訳の要件」は2段で整理する：会計システムに求められる仕訳の全体要件（1-1 外部報告・管理会計・内部統制のための記録）と、それを踏まえて固定資産システムの仕訳に求められる代表的な要件（1-2 固定資産台帳と総勘定元帳の同期〔BS〕、1-3 固定資産台帳に基づく費用・収益の計上〔PL〕、1-4 他システムの仕訳の消し込み、の順）。1-4 は、債権・債務管理・購買管理・工事・プロジェクト管理・経費精算などのシステムや、グループ会社間の照合が存在する場合に意識する要件として書き、特定のシステムの存在を前提にしない。リース資産の仕訳は別で扱うので含めない。すべてを網羅するとは書かない。3章の勘定科目がどれかの要件に必ず対応するようにする。分類の表を作るより、話の範囲（粒度）がそろうように文章で位置づける。これらと伝票の貸借一致はどのユーザーでも求められる。それ以外は方針として扱う
- 全体の構成は、仕訳の要件 → 仕訳の入力項目（ヘッダ・明細）→ 固定資産に関係する勘定科目 → 固定資産に関係する伝票の種類。項目・勘定科目・伝票の種類は、どの要件のためにあるかで説明する
- ERPの項目は、ユーザーごとに次の点が異なる前提で整理する
  - 項目の有無：存在しない項目がある（例：取引日がない、伝票の種類がない、BSとPLのセグメントを分けていない）
  - 持ち方：どの項目をヘッダで持ち、どの項目を明細で持つか
  - 構成：セグメントとして持つ項目と、その細かさ
  - 編集のルール：同じ項目でも、何から・どう編集するか
- 方針によって変わる点は「バリエーション」として示す
- 仕訳例は、ある方針を採った場合の一例として示す
- 「確認すべきポイント」や検証チェックリストは書かない（2026-11-22）。何が起きうるか・何が方針で変わるかを書けば足りる
- どの項目の話かが分かるよう、ERPの項目名は［勘定科目］のように括弧で示す
- 繰り返し・重複を避ける。要件・入力項目・勘定科目の説明は1か所にまとめ、伝票の種類ごとの節では各伝票に固有の点だけを書き、ほかは参照先（「1部 同期の条件」など）を示す
- 同じ章の節は、記載の粒度と並びをそろえる。1章（仕訳の要件）の各節は「要件／なぜ必要か／対象（勘定・相手）／単位・条件」の順に書き、伝票の種類ごとの細かい手順は4章に置いて参照で済ませる
- 2章（仕訳の入力項目）は、各項目がどの要件（1-1〜1-4）のためにあるかと、固定資産の仕訳での使い方を、1章と同じ粒度で書く。勘定科目と伝票の種類の中身（伝票の種類ごとの日付など）は3・4章に任せる
- 特定のERPパッケージに引きずられた用語（モジュール、機能領域など）を使わず、一般的な言葉で書く
- 「重要になる」「注意が必要」「意識する」のような、何をどうするかが分からない表現で終わらせない。具体的に何を分ける・そろえる・記録する必要があるかを書く
- 初めて出る独自の呼び方（掛け金、BSセグメントなど）は、その場で意味を一言添える。「なぜそうなるか」（例：なぜ一致が崩れるか、なぜ消し込みが必要か）を省かない
- 聞き手に向けた内容と、書き手（Claude）への指示を混ぜない。後者は骨子の前提条件かこのファイルに置き、スライドには載せない

# 用語

骨子・スライド・ノートの言葉はこの定義に合わせる。同音異義・多義の言葉は定義した意味だけで使い、意味のない言いかえはしない。

## 用語の定義

| 用語 | 本資料での意味 | 使い方の注意 |
|---|---|---|
| ERP | 固定資産システムが仕訳を連携する先の会計システム（会計パッケージを含む） | SuperStream-NX など会計に特化した製品も、まとめてERPと呼ぶ |
| 連携 | 固定資産システムからERPへ仕訳を渡すこと | － |
| 台帳 | 固定資産台帳 | 固定資産システムが、会計・税務・IFRSなど複数の台帳を持つことがある。どの台帳がERPのどの帳簿に対応するかを確認する |
| 元帳 | 総勘定元帳 | － |
| 帳簿 | 会計基準などで分ける記帳先（日本基準・IFRS・管理用など） | 製品によって「元帳」「帳簿」と呼び方が違う |
| 資産勘定 | 建物・機械装置などの勘定。間接法で表示する資産では取得価額、直接法で表示する資産では帳簿価額（取得価額から減価償却・減損の累計を差し引いた額）を記帳する | 「取得価額の勘定」と限定しない |
| 固定資産勘定 | 資産勘定・減価償却累計額・減損損失累計額の総称 | 台帳と元帳の一致の対象。「固定資産勘定の行」は、これらの勘定の行を指す |
| 減価償却累計額・減損損失累計額 | それぞれの累計額の勘定 | 「累計額」だけではどちらか分からないため、省略しない。「累計額方式」は、減損損失累計額を使う減損の計上方式 |
| 費用・収益の勘定 | 減価償却費・売却損益・除却損などの、PL（損益計算書）の勘定 | 簿記の「損益勘定」（決算で収益・費用を集める集合勘定）と紛らわしいため、「損益勘定」とは呼ばない。「損益」だけで書くときは、業績としての利益・損失を指す |
| 掛け金 | 未払金・未収入金（後で支払・入金する債務・債権） | 保険などの「掛金」とは別 |
| セグメント | 勘定科目以外で、仕訳の集約先となる項目（事業・部門・プロジェクト・取引先など） | 製品によって意味が違う（Oracle EBS では勘定科目を含む勘定組合せの各要素、SAP では外部報告用の特定の項目）。外部報告のセグメントは「外部報告セグメント」と呼んで区別する |
| 振替 | 伝票の種類としては、台帳の資産の種類・セグメントの変更による固定資産勘定の付け替え | 一般には勘定間の付け替え全般を指す。ほかの付け替えは「減価償却費の振替」のように対象を付けて書く |
| 伝票の種類・資産の種類 | 伝票の種類＝取得・売却・振替・除却・減損・圧縮記帳・減価償却・過年度の訂正の区分。ERPでは［伝票の種類］の項目で持つ（持たない・まとめるユーザーもある）。資産の種類＝建物・機械装置などの区分 | 「仕訳の種類」とは書かない。有形固定資産・無形固定資産などの区分は「分類」と呼ぶ |
| 伝票番号・参照番号 | 伝票番号＝伝票を識別する番号。参照番号＝元の取引や連携元のシステムで採番した番号 | 採番のしかたは要件次第。「ERPで伝票番号を採番し、固定資産システムで採番した伝票番号は参照番号に入れる」は事例が多い形として書き、決めつけない |
| 同期 | 固定資産台帳と総勘定元帳の残高が一致し続けること（仕訳の要件の1つ） | 「本勘定元帳」ではなく「総勘定元帳」と書く |
| 減価償却 | 有形・無形固定資産の減価償却 | 繰延資産は「償却」、長期前払費用は「費用化」と書く。仕訳の形は同じなので、減価償却費の節（骨子 4-5・4-6）でまとめて扱う |
| 用途 | 資産を利用する部門の区分（製造・販売・管理など） | 減価償却費の勘定科目を、用途別に分けるユーザーがある |
| 記帳日・取引日 | 記帳日＝会計期間を決める日、取引日＝取引が発生した日 | 製品によって呼び方が違う（例：転記日付・計上日、伝票日付・証憑日付） |
| 方針・設定 | 方針＝ユーザーが決める会計処理のやり方、設定＝システムのマスタ（勘定科目テーブルなど） | － |

## 統一する書き方（左の表記は使わない）

| 使わない | 使う |
|---|---|
| 損益勘定 | 費用・収益の勘定（「損益」単独は業績としての利益・損失、勘定科目名「売却損益」だけ） |
| 償却費 | 減価償却費（勘定科目名の例「ソフトウェア償却費」「繰延資産償却」は可） |
| 償却（有形・無形の処理） | 減価償却（繰延資産は「償却」、長期前払費用は「費用化」） |
| 累計額（単独） | 減価償却累計額／減損損失累計額（「累計額方式」は可） |
| 減損累計額 | 減損損失累計額 |
| 資産勘定（3勘定の総称として） | 固定資産勘定。建物・機械装置などの勘定だけを指すときが資産勘定 |
| 事業部 | 事業 |
| PJ、プロジェクト・案件 | プロジェクト（例の値「PJ-a」は可） |
| 分析軸 | 切り口 |
| 利用セグメント | 用途 |
| ERP側、会計システム | ERP |
| 固定資産側 | 固定資産システム |
| 導入先 | ユーザー |
| 債務・債権（システム名） | 債権・債務 |
| 債権・債務モジュール、モジュール | 債権・債務管理システム、システム（特定のERPパッケージの用語を使わない） |
| 消込 | 消し込み |
| 設例 | 例 |
| 仕訳の例 | 仕訳例 |
| 相手方 | 相手勘定 |
| 科目 | 勘定科目（「補助科目」「財務諸表の科目」は可） |
| 仕訳の種類 | 伝票の種類 |
| 方針によらない原則 | 仕訳の要件 |
| 方針によって変わる点 | バリエーション |
| （方針・設定による） | （方針による） |
| BS・PL | BSとPLのセグメント |
| 連動、連動あり・連動なし | 独自の呼び方は使わない。「掛け金・消費税を固定資産システムで計上する／債権・債務管理システムで計上する」「取得・売却のデータを受け渡す」と書く |
| 連携用の仮勘定、連動用の仮勘定、連携データ | 債権・債務管理システムとの間の仮勘定、受け渡すデータ |
| 振替範囲、振替仕訳 | 振り替える範囲、振替の仕訳 |
| 期待結果 | 期待される仕訳 |
| 属性（台帳の） | 台帳の資産の種類・セグメント |
| セグメント資産 | 外部報告セグメントごとの資産 |

## 仕訳例の勘定科目名

売却損益、除却損、減損損失、圧縮損、取得仮勘定、売却仮勘定、減価償却累計額、減損損失累計額、未払金、未収入金、仮払消費税、仮受消費税。セグメントの例は BS＝事業（事業X・事業Y）、PL＝部門・プロジェクト（製造1課・販売1課・PJ-a・PJ-b）。

## スライドへの載せ方

用語だけを集めたスライドは作らない。聞き手に必要な定義は、その言葉が初めて出るスライド（ヘッダ項目・明細項目など）に書く。

## メンテナンス

- 用語を足す・変えるときは、このファイルを更新し、骨子・スライド・ノートを grep して表記をそろえる
- 変更は骨子の決定事項ログにも残す
