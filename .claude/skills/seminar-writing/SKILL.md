# 固定資産仕訳セミナーの整理と記述のルール

## 整理の基本姿勢

受講者向けの内容ではなく、内容を整理・記述するときの約束事。スライドには載せない。

- 仕訳の形はユーザーごとの方針で変わる。「必ずこうなる」と断定せず、基本となる考え方とバリエーションとして書く
- 方針によって変わる点は「バリエーション」として示す
- 仕訳例は、ある方針を採った場合の一例として示す
- 「確認すべきポイント」や検証チェックリストは書かない（2026-11-22）。何が起きうるか・何が方針で変わるかを書けば足りる
- どの項目の話かが分かるよう、ERPの項目名は［勘定科目］のように括弧で示す
- 繰り返し・重複を避ける。要件・入力項目・勘定科目の説明は1か所にまとめ、伝票の種類ごとの節では各伝票に固有の点だけを書き、ほかは参照先（「1部 同期の条件」など）を示す
- 同じ章の節は、記載の粒度と並びをそろえる（章ごとの並びは references/骨子の構成.md）
- 特定のERPパッケージに引きずられた用語（モジュール、機能領域など）を使わず、一般的な言葉で書く
- 「重要になる」「注意が必要」「意識する」のような、何をどうするかが分からない表現で終わらせない。具体的に何を分ける・そろえる・記録する必要があるかを書く
- 初めて出る独自の呼び方（掛け金、BSセグメントなど）は、その場で意味を一言添える。「なぜそうなるか」（例：なぜ一致が崩れるか、なぜ消し込みが必要か）を省かない
- 聞き手に向けた内容と、書き手（Claude）への指示を混ぜない。後者は骨子の前提条件かこのファイルに置き、スライドには載せない
- 骨子の構成と、用語の定義はテーマ別に references/ に置いた（2026-11-22）。書く・直す前に、関係するファイルを読む

調べた内容の記録（調査メモ）は、リポジトリの reference/ に置く。skill の references/ は書き方のルール、reference/ は内容の裏付けで、役割が違う。

## スライドへの載せ方

用語だけを集めたスライドは作らない。聞き手に必要な定義は、その言葉が初めて出るスライド（ヘッダ項目・明細項目など）に書く。

## メンテナンス

- 用語を足す・変えるときは、テーマの合う references/ のファイルを更新し、骨子・スライド・ノートを grep して表記をそろえる。合うテーマがなければファイルを足し、上の表に加える
- 用語は1つのファイルにだけ書く（定義が2か所に分かれないようにする）
- 変更は骨子の決定事項ログにも残す
