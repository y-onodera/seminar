# 1章 仕訳の要件：用語と調査で分かったこと

骨子 1章（1-1 外部報告・管理会計・内部統制のための記録、1-2 固定資産台帳と総勘定元帳の同期、1-3 固定資産台帳に基づく費用・収益の計上、1-4 他システムの仕訳との同期）を書くときに読む。章の組み立ては [骨子の構成.md](骨子の構成.md)。詳しい調査の経緯と出典は、リポジトリの `調査メモ/` の各ファイル。

## 用語の定義

| 用語 | 本資料での意味 | 使い方の注意 |
|---|---|---|
| ERP | 固定資産システムが仕訳を連携する先の会計システム（会計パッケージを含む） | SuperStream-NX など会計に特化した製品も、まとめてERPと呼ぶ |
| 連携 | 固定資産システムからERPへ仕訳を渡すこと | － |
| 台帳 | 固定資産台帳 | 固定資産システムが、会計・税務・IFRSなど複数の台帳を持つことがある。どの台帳がERPのどの帳簿に対応するかを確認する |
| 元帳 | 総勘定元帳 | － |
| 帳簿 | 会計基準などで分ける記帳先（日本基準・IFRS・管理用など） | 製品によって「元帳」「帳簿」と呼び方が違う |
| 同期 | 固定資産台帳と総勘定元帳の残高が一致し続けること（1-2） | 「本勘定元帳」ではなく「総勘定元帳」と書く |
| 個別仕訳・定型仕訳 | 個別仕訳＝台帳で取引を登録するたびに作る仕訳（取得・売却・振替・除却・減損・圧縮記帳・訂正・取消）。定型仕訳＝決まった時期に台帳の対象資産全体からまとめて作る仕訳（減価償却）（1-2） | 減損は個別仕訳として扱う。「日次で取引ごと」「月次で集約」のような言いかえで代えない。個別仕訳を月次でまとめて伝票にする場合も、個別仕訳と書く |
| 逆仕訳 | 元の仕訳と同じ勘定科目・セグメント・金額で、貸借を反対にした仕訳（1-2 の取消で作る） | 「反対仕訳」とは書かない |
| 照合 | 1つの取引の仕訳を、固定資産システムとほかのシステムが分担して計上する場合に、両方の仕訳が同じ取引の同じ内訳を指していることを確かめること（1-4）。消し込み（一方の残高を他方の反対の仕訳で消してゼロにする）と、突き合わせ（残高は消さず、両方の記録の一致を確かめる）の2つの形がある。照合の単位には［取引先］［参照番号］［税区分］［プロジェクト］［関係会社］などを使う | 「消し込み」は残高をゼロにする場合だけに使う。グループ会社間の債権・債務、消費税の申告との一致は「突き合わせ」と書く |

## 統一する書き方（左の表記は使わない）

| 使わない | 使う |
|---|---|
| つなぐ勘定（他システムの仕訳とつなぐ勘定） | 照合の対象（「他システムとの照合の対象になる勘定の行」「照合の対象の単位」など）（2026-11-25） |
| ERP側、会計システム | ERP |
| 固定資産側 | 固定資産システム |
| 導入先 | ユーザー |
| 債務・債権（システム名） | 債権・債務 |
| 債権・債務モジュール、モジュール | 債権・債務管理システム、システム（特定のERPパッケージの用語を使わない） |
| 連動、連動あり・連動なし | 独自の呼び方は使わない。「債権・債務・消費税を固定資産システムで計上する／債権・債務管理システムで計上する」「取得・売却のデータを受け渡す」と書く |
| 連携用の仮勘定、連動用の仮勘定、連携データ | 債権・債務管理システムとの間の仮勘定、受け渡すデータ |
| 消込 | 消し込み |

## 調査で分かったこと

### 1-1 管理会計の用途と業種・業態（調査メモ：1-1_管理会計の用途と業種.md）

| 用途と業種・業態の例 | 確かさ | 要点 |
|---|---|---|
| 業績評価：多店舗の小売・外食（店舗別損益） | 公開資料で裏付けあり | 減損会計で店舗単位に資産をまとめ、店舗損益の悪化を減損の兆候としている。店舗の資産と費用・収益を店舗の切り口で記録している |
| 業績評価：建設・IT受託開発（プロジェクト別）、不動産賃貸（物件別） | 一般論 | プロジェクト別・物件別に損益を見ることは一般的。減価償却費の行にプロジェクト・物件を持たせるかは確認できていない |
| 原価管理：製造業 | 一般論 | 工場の減価償却費は製造間接費。工場・ライン（部門）ごとに集めてから、機械運転時間などで製品に配賦する。仕訳では、減価償却費を資産を使う部門の行に計上しておくことが出発点 |
| ROIC：資本集約型の事業 | 公開資料で裏付けあり（個社は未確認） | 投下資本＝運転資本＋固定資産のROICは事業部門別に展開しやすく、資本集約型の事業で導入が多い。細かくしすぎず事業単位で見るのが望ましいとされる。固定資産勘定の行に事業の切り口が要る |

- 骨子への反映は未定（反映案は調査メモの3章）

### 1-4 他システムの仕訳との同期（調査メモ：1-4_他システムとの照合.md）

- 照合を「1つの取引を2つのシステムが分担して計上したときに、両方の行が同じ取引の同じ内訳を指しているか」と捉える。取得・売却では、本体（資産・売却額）は固定資産システム、税額・債権・債務は債権・債務管理システム、と分かれることが多い。仮勘定の合計が合うだけでは足りず、税区分ごとに合っている必要がある
- 照合キー：［取引先］＋［参照番号］（請求書・発注・検収・工事・精算番号など）＋［税区分］＋金額（税抜）＋セグメント。期末の切り分けに［会計日付］も使う
- 粒度：明細（［参照番号］×［税区分］）＞ 取引先 ＞［勘定科目］× セグメントの残高。税額は請求書ごと・税率ごとに端数処理するので、税額の照合の単位は「資産」ではなく「請求書 × 税区分」
- 仕訳の分担の形は3つ（調査では製品名で調べた。骨子では製品名を使わない）
  - 1つの伝票で記帳する：資産・税額・債権・債務が同じ伝票に入り、間の仮勘定がない。照合が要らない。税区分は資産（売却額）の行に付く
  - 仮勘定を使い、データを受け渡す：明細のひも付けはシステムが行い、照合は「まだ受け渡していない明細」を見つけることになる。税区分は債権・債務の側にある
  - 仮勘定を使い、データを受け渡さない：照合キー（参照番号・税区分）を仮勘定の行に持たせ、人が消し込む
- ERPの外にある固定資産システムとERPの間は、「データを受け渡す」か「受け渡さない」形になる。固定資産システムで債権・債務・消費税まで計上する場合、ERPの未払金・未収入金が取引先ごとの明細を持つ勘定だと、元帳への仕訳の連携では取引先の明細を作れない（債権・債務の入口から入れるか、元帳の勘定として持つ必要がある）
- 相手ごとの照合の形：債務管理（取得）・債権管理（売却）・購買管理・工事・プロジェクト管理・経費精算は消し込み、グループ会社と元帳全体（消費税の申告）は突き合わせ

### 1-4 照合先ごとの資産の例（調査メモ：1-4_照合先ごとの資産の例.md）

- システムの経路（請求書・発注・検収・建設仮勘定から固定資産へ）は、パッケージの資料で確認できた
- 工事・プロジェクト管理を経由する資産（鉄道の設備・車両、小売の新設・改装、製造業の設備）は、導入事例と有価証券報告書の両方で確かめられた
- 購買管理を経由する資産は、システムの経路の直接の記載はなく、近い裏付け（情報機器を購買部門が管理、店舗の什器・レジ）にとどまる
- 債権管理を経由する売却（建設機械レンタルの中古販売）と、グループ会社間の固定資産の売買は確かめられた
- 経費精算から固定資産へ資産を渡す流れは、裏付けがとれなかった
- 資産の種類 × 業種・業態の組み合わせは、導入事例にはほとんど書かれていない
- 骨子の表の「資産の例」は、固定資産の種類名（機械装置・工具器具備品・建物など）だけで書く。業種と組み合わせた具体例（「鉄道会社のホームドア」など）は骨子に書かず、調査メモに置く（2026-11-23）

### 1-4 消費税（調査メモ：1-4_他システムとの照合.md の3-7・6章）

- 会計システムの税区分の役割は、税額の計算と消費税の行の自動作成、申告のための集計、仕入税額控除の区分（個別対応方式）、決算での精算（控除対象外消費税を含む）。骨子 1-4 に入れたのは「精算・集計」だけ
- 税込経理では仮払・仮受消費税の行を作らないが、申告の集計に税区分は使う
- 照合ではないが税区分を台帳で持つ理由になる話（骨子には未反映）：調整対象固定資産、控除対象外消費税の処理、居住用賃貸建物、高額特定資産
