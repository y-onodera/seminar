# 2章 仕訳の入力項目：用語と調査で分かったこと

骨子 2章（ヘッダ・明細の項目、セグメント、取引先・税区分）を書くときに読む。詳しい調査の経緯と出典は、リポジトリの `調査メモ/2_ERP4製品の仕訳ファイル.md`。

## 用語の定義

| 用語 | 本資料での意味 | 使い方の注意 |
|---|---|---|
| セグメント | 事業・部門・プロジェクトなどの切り口（骨子 1-1）の総称。本資料での定義で、ERPの仕様上の項目とは関係しない | 「管理の切り口」「切り口」と言いかえない。外部報告のセグメント情報の単位は、一般の会計用語の「報告セグメント」と書く（「外部報告セグメント」とは書かない）。ERPの項目名ではないので、［セグメント］のように括弧で書かない。製品ごとの「セグメント」の意味（Oracle EBS では勘定科目を含む勘定組合せの各要素、SAP では外部報告用の特定の項目）では使わない。外部報告のセグメントは「外部報告セグメント」と呼んで区別する |
| 用途 | 資産を利用する部門の区分（製造・販売・管理など） | 減価償却費の勘定科目を、用途別に分けるユーザーがある |
| 伝票番号・参照番号 | 伝票番号＝伝票を識別する番号。参照番号＝元の取引や連携元のシステムで採番した番号 | 採番のしかたは製品・ユーザーごとに異なる。「ERPで伝票番号を採番し、固定資産システムで採番した伝票番号は参照番号に入れる」は事例が多い形として書き、決めつけない。債権・債務管理システムなどとの照合のために、参照番号に相手と同じ番号（請求書番号・発注番号など）を編集して入れる形もある（1-4） |
| 記帳日・取引日 | 記帳日＝会計期間を決める日、取引日＝取引が発生した日 | 製品によって呼び方が違う（例：転記日付・計上日、伝票日付・証憑日付） |

## 統一する書き方（左の表記は使わない）

| 使わない | 使う |
|---|---|
| 事業部 | 事業 |
| PJ、プロジェクト・案件 | プロジェクト（例の値「PJ-a」は可） |
| 分析軸、管理の切り口 | セグメント |
| 利用セグメント | 用途 |
| BSセグメント・PLセグメント、BSとPLのセグメント | 固定資産勘定の行のセグメント／費用・収益の行で加わるセグメント（部門・プロジェクトなど）。「BSとPLのセグメントを分ける場合」は「費用・収益の行に部門・プロジェクトを持たせる場合」 |
| 属性（台帳の） | 台帳の資産の種類・セグメント |
| セグメント資産 | 報告セグメントごとの資産 |
| 外部報告セグメント | 報告セグメント |

## 調査で分かったこと：ERP 4製品の仕訳ファイル（調査メモ：2_ERP4製品の仕訳ファイル.md）

2章の一般論の表は、SAP S/4HANA・Oracle EBS（R12）・SuperStream-NX・EXPLANNER/Ax の調査をもとにしている。製品名と製品ごとの項目名は調査のための言葉で、骨子・スライドでは使わない。

- 4製品の考え方
  - SAP：明細ごとに勘定タイプ（G/L・得意先・仕入先・資産）で記帳する。利益センタ・セグメントなどはマスタと設定から派生する。ファイルに入れる量は少なめ
  - Oracle EBS：勘定も部門も、セグメント値の組合せ（勘定科目組合せ）で表す。取引先などの明細は補助元帳が持ち、総勘定元帳への仕訳には取引先を持たない
  - SuperStream-NX：勘定科目・補助科目・部門・相手先を、意味の決まったコードで持つ。切り口は機能コード・プロジェクト・セグメントコードで加える
  - EXPLANNER/Ax：振替伝票の明細に、勘定科目・補助科目・部門・取引先と、セグメント管理項目10種を持つ
- 一般論にするときに効いた違い（項目の有無・持ち方が製品で違う、という前提の根拠）

| 観点 | 製品による違い |
|---|---|
| ファイルの構造 | ヘッダと明細に分ける製品と、明細1行ずつの平坦な表で毎行にヘッダの値を持つ製品がある |
| 勘定の表し方 | 勘定科目＋補助科目、勘定タイプ別の勘定、セグメントの組合せ全体を1つの勘定とする、など |
| 管理の切り口 | 意味の決まった項目（原価センタ・利益センタなど）を持つ製品と、意味をユーザーが決めるセグメントを持つ製品がある |
| 取引先 | 仕訳に持つ製品と、補助元帳だけが持ち総勘定元帳への仕訳には持たない製品がある |
| 税 | 税区分から税の明細を自動で作る製品と、補助元帳で税を計算し総勘定元帳では扱わない製品がある |
| 日付 | 会計期間を決める日と証憑の日付を両方持つ製品と、会計期間を決める日だけの製品がある |
| 貸借一致の単位 | 会社だけでなく、利益センタ・セグメント・部門などの単位でも貸借を合わせる仕組みを持つ製品がある |
| 並行会計 | 日本基準・IFRSなどの帳簿を並行して持つ仕組みは、どの製品にもある（呼び方は元帳・帳簿など） |

- 部門の扱い：目的別に原価センタ（費用）と利益センタ（損益・貸借対照表）に分ける製品、セグメントの1つとする製品、独立した部門コードとする製品がある。部門を固定資産勘定の行に持つか、費用・収益の行だけに持つかが製品で異なる
- 確かさ：SAP・Oracle EBS は製品の一般的な仕様、SuperStream-NX・EXPLANNER/Ax は公開資料の範囲。後者の列構成・税・日付などは未確認の点が多い
